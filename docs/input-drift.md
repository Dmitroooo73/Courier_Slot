# Дрейф входных данных

Во вкладке «Мониторинг → Изменение данных» видно, отличаются ли последние данные от зафиксированного опорного периода. Сигнал служит поводом проверить источник и точность прогноза. Ошибка прогноза измеряется отдельно во вкладке «По заказам».

## Окна и признаки

- Текущее окно — 14 последних закрытых дат прогноза по Москве. Для каждой даты заказа используются только лаги D−2, D−7, D−14 и среднее D−8…D−2 из общей функции признаков. Поэтому результаты по заказам относятся к входам модели и могут отставать от последних фактических заказов.
- Опора — 56 дат непосредственно перед первым текущим окном с достаточной опорой. Сохраняем границы, исходные значения и SHA-256. Следующие проверки используют ту же опору. Изменение опоры или алгоритма требует новой версии правила.
- Заказы считаем по шести зонам. Для каждого признака вычитаем медиану соответствующего дня недели в опорной выборке этой зоны. Так обычная разница между буднями и выходными меньше влияет на сигнал.
- Погодные признаки берём из того же архива прогнозов Open-Meteo с заблаговременностью 48 часов. Температуру, осадки и число часов с осадками сравниваем по Москве. Обычная смена сезона тоже может дать сигнал, поскольку распределение входных значений меняется.
- Нужны минимум 42 пригодных значения из 56 для опоры и 10 из 14 для текущего окна по каждому признаку. Для заказов дополнительно нужны хотя бы четыре опорных и одно текущее значение на каждый день недели. Пропуски не заменяются нулями или более старыми днями. Опора фиксируется после выполнения требований к опорным выборкам всех признаков.

## Правило `input-drift-v1`

Мера изменения — максимальный разрыв между долями наблюдений ниже или равных одному и тому же значению. Это расстояние между эмпирическими функциями распределения. При разрыве от 45 процентных пунктов показываем сигнал. Это выбранный порог для диагностики в учебном проекте. Он не калибровался по частоте ложных срабатываний и не задаёт статистический уровень значимости. [Определение расстояния в двухвыборочном критерии Колмогорова — Смирнова](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/ks2samp.htm).

В интерфейсе показываем медианы исходных значений, размеры выборок и сигнал. Разрыв учитывает форму распределения, поэтому сигнал возможен и при близких медианах. Зависимые лаги могут сигнализировать об одном и том же изменении одновременно.

## Запуск и хранение

Worker проверяет последнее закрытое окно при запуске и после полуночи по Москве. Он читает сохранённые CSV и погодный кэш. Отсутствующие файлы отражаются в покрытии выборки. При ошибке чтения worker повторяет попытку по существующему расписанию повторов.

В PostgreSQL опора лежит в `drift_references`, а проверки в `drift_reports` по версии правила и последней дате окна. Первая опора и результат сохраняются одной транзакцией. Повторный запуск за ту же дату возвращает сохранённый результат через `GET /api/dashboard` в поле `input_drift`. В файловом режиме опора и проверки находятся в `data/drift/input-drift-v1/`.

Первая проверка рабочего архива использовала опору с 4 сентября по 29 октября 2026 года и текущее окно с 30 октября по 12 ноября. На Востоке четыре признака заказов уложились в порог. Медиана прогнозной температуры по Москве снизилась с 11,365 до 2,135 °C, разрыв распределений составил 89,29 п. п. При интерпретации учитываем, что окна пришлись на разные части осени.
