# Реестр моделей

Открывается во вкладке «Качество». В карточке есть дата расчёта, состояние, период итогового обучения, признаки и результаты временной проверки. Метка «Рабочая версия» показывает, какая версия сейчас считает ежедневный прогноз. «Версия выбранного прогноза» связывает карточку с открытой датой. Статус в паспорте говорит, откуда версия появилась: «Прогноз опубликован» — версии периода, когда модель обучалась каждый вечер; «Сохранена для проверки» — первая версия или отдельная команда; «Проверялась как новая версия» — кандидат по правилу [обновления модели](model-lifecycle.md), принятый или отклонённый.

## Как хранится версия

- Сохраняется тот экземпляр Ridge или CatBoost, который рассчитал прогноз, включая обученные преобразования Ridge. Для сезонной базы хранится правило повторения спроса недельной давности.
- Паспорт содержит список и версию признаков, параметры, seed, SHA-256 набора, даты и размер обучающей выборки, версии Python и библиотек, метрики валидации и отложенного теста. Метрики относятся к временной проверке метода до итогового обучения на всех доступных закрытых датах. Для отложенного теста указан отдельный конец обучения.
- PostgreSQL хранит паспорт и двоичный артефакт в `model_versions`. Ежедневная публикация добавляет версию, отчёт, запуск и исходный снимок прогноза в одной транзакции. `model_version_id` связывает эти записи. Архивные прогнозы, созданные до реестра, открываются как прежде.
- В файловом режиме паспорт и артефакт сохраняются одним файлом в `data/model_registry/` до отчёта. Bootstrap переносит версии и отчёты в PostgreSQL.
- `GET /api/models` возвращает паспорта с пагинацией. `GET /api/dashboard` возвращает паспорт выбранного прогноза в `forecast_model`. Двоичный артефакт доступен внутреннему процессу через хранилище.

Рабочие модели сериализуются внутренним процессом. При загрузке проверяются контрольная сумма, версия признаков и окружение. Формат pickle предназначен для артефактов от доверенного процесса обучения. [Документация scikit-learn о сохранении моделей](https://scikit-learn.org/stable/model_persistence.html).

## Запуск

После `docker compose up -d --build` init создаёт таблицы. Сохранить отдельную обученную версию для сравнения, не меняя рабочую, можно так (дата — с доступными данными):

```powershell
docker compose exec -T worker python -m backend.modeling --data-dir /app/data --date 2026-11-13
```

Команда добавляет версию в реестр и печатает её метрики. Опубликованные прогнозы не меняются. Какая версия считает ежедневный прогноз, как проверяется новая и как вернуть предыдущую — в [model-lifecycle.md](model-lifecycle.md).
