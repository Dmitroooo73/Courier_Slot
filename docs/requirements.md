## Воспроизводимые проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
npm --prefix frontend test
npm --prefix frontend run build
```

HTTP-тесты требуют `PULT_TEST_DATABASE_URL` и создают случайную схему `pult_test_*`, которую удаляют после завершения. Без этой переменной они явно пропускаются. В Docker все проверки, включая MinIO:

```powershell
docker compose run --rm --no-deps -e PULT_DATABASE_URL= -e "PULT_TEST_DATABASE_URL=host=db dbname=pult user=pult" web python -m unittest discover -s backend/tests -v
```

Перед этим образ должен быть собран из текущего кода. Модульные файловые тесты также принудительно отключают `PULT_DATABASE_URL` внутри себя. Тестовые аккаунты не попадают в рабочие таблицы.

Полный повтор расчёта с новыми текстовыми журналами и уже загруженной погодой:

```powershell
docker compose exec worker python -m backend.modeling.verify_reproduction --date 2026-11-11
```

Проверка создаёт временный каталог, строит 365 журналов, сравнивает SHA-256, прогнозы, параметры, метрики и сценарии с сохранённым отчётом, затем проверяет повторную загрузку. Дату надо выбирать из имеющихся отчётов.

## Сценарии ручной приёмки

Главный экран «Курьер»: состояние нехватки данных, три явно вымышленных примера, сравнение с дорогой и без, отсутствие обещаний заработка и реального времени. Отдельное описание — `courier-scenario.md`.

1. Прогноз: все шесть зон, выбор карты/списка, разные даты, переход в качество, объяснение расчёта.
2. Качество: главный результат сверху, понятные единицы, смена периода важности; сценарий внизу, изменение одного условия и сброс.
3. Мониторинг: ожидающая сверка объясняет дату; история решений раскрывается по датам и переключается вместе с зоной; учебный режим проходит 0 → 7 → 14 дней, обычный спрос показывает 0% и не меняет серверную историю.
4. Журнал: раскрытие запуска и открытие связанного прогноза.
5. Аккаунт: вход остаётся после перезагрузки; поля скрыты до «Редактировать»; сохранение профиля, аватар и пароль.
6. Админка: поиск, фильтры, блокировка и разблокировка; обычному пользователю доступ закрыт.
7. Узкий экран: нет горизонтального переполнения страницы; таблицы могут прокручиваться внутри своего блока.
8. Перезапуск контейнеров: отчёты, аккаунты и аватары сохраняются в томах. Отдельно проверить развёртывание на другом компьютере и доступность образа MinIO.

- Docker: обновлены web/init/worker, PostgreSQL здоров, приложение отвечает на порту 8765; рабочие тома сохранены.
- В собранном образе прошли все 25 серверных тестов, включая HTTP, PostgreSQL и настоящий MinIO. Тестовые аккаунты создавались только в отдельной временной схеме.
- Пять тестов frontend и production-сборка прошли. [GitHub Actions](https://github.com/Dmitroooo73/Courier_Slot/actions/runs/43327317722) завершился успешно: в CI проверка MinIO пропускается, поскольку там нет этого сервиса; локально она выполнена.
- В браузере подтверждены три состояния учебного совета, сброс ползунка обычного спроса до нуля, восстановление входа после перезагрузки и скрытые по умолчанию поля профиля.
- На ширине 320 px у всех семи вкладок нет горизонтального переполнения страницы. В консоли при переходах ошибок не обнаружено.
- Живой мониторинг содержит факты за 11–12 ноября, ждёт закрытия 13 ноября и честно сообщает, что для первого недельного вывода нужно семь дней. Планировщик успешно сверил новый закрытый день после перезапуска.

Это результаты конкретного прогона, а не гарантия отсутствия любых ошибок. Развёртывание на другом компьютере и полный цикл управления версиями моделей ещё не проверены.

## Итоговая приёмка 13 ноября 2026

Изменения: прогноз сохранённой рабочей версией, проверка новой версии, замена и откат, учебный цикл, карта из округов, погода «сейчас», новый образ MinIO по умолчанию.

- **Тесты.** В Docker прошли 49 серверных тестов с PostgreSQL и настоящим MinIO, без пропусков. Прошли 5 тестов frontend и production-сборка.
- **Рабочий стенд.** Контрольные суммы до и после обновления совпали: 7 отчётов, 3 наблюдения, 12 решений, дрейф, реестр, 16 запусков, аккаунты. Рабочей назначена версия от 13 ноября после сверки с архивным прогнозом этой даты. Аватар в MinIO на месте; том создан 10 ноября и не пересоздавался.
- **Перенос на чистую копию.** Файлы репозитория без `data/` и `.env` скопированы в пустую папку и подняты отдельным проектом Compose со своими томами. Через 51 секунду после старта контейнеров worker опубликовал прогноз сохранённой моделью, проверил дрейф и построил учебный цикл. Метрики совпали с рабочим стендом (промах 5,86, валидация 5,59). Внутри чистого стенда прошли все 49 тестов, включая загрузку аватара в MinIO из образа `bitnamilegacy/minio`. После `down` и `up` данные сохранились, а worker не стал переобучать модель.
- **Найдено при переносе и исправлено.**
  - Образ `minio/minio` удалён из Docker Hub: API отвечает 404, quay.io требует авторизацию. По умолчанию теперь Bitnami-сборка по digest (amd64 и arm64).
  - На пустой базе первая версия модели записывалась после указателя на неё и нарушала внешний ключ. Порядок исправлен, добавлен тест.
- **Браузер.** На ширине 320 px у всех вкладок нет горизонтального переполнения. Проверены:
  - блок «Обновление модели» в виде администратора (сессия подменена только в браузере, в базе аккаунт не создавался);
  - режим «Замена модели»;
  - карта округов и погода «сейчас».

  В консоли только ожидаемый 401 при проверке сессии анонимом.
- **API.** Отвечают `/api/models`, `/api/lifecycle-demo`, `/api/weather/now`, `/api/dashboard`. Неверная зона даёт 422, анонимные действия администратора — 401. Права, повтор запроса, конфликт версии и откат покрыты HTTP-тестами.

Не проверено: перенос на физически другой компьютер — проверялась изолированная копия на этом. Автоматический откат не реализован, решение принимает администратор.
