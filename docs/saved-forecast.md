# Ежедневный прогноз сохранённой моделью

Прогноз и обучение разделены. Каждый вечер worker берёт рабочую версию из `active_forecast_model`, загружает её артефакт из реестра и считает прогноз без обучения. Полное описание рабочей версии, проверки новой, замены и отката — в [model-lifecycle.md](model-lifecycle.md).

Для прогноза на дату D worker читает только заказы за D−14…D−2 и погодный выпуск на D. Перед расчётом он проверяет:

- контрольную сумму артефакта;
- версию признаков и окружение;
- что версия обучена не позже D−2, иначе прогноз запрещён как использующий будущие данные.

Отчёт помечается `forecast_mode = saved_model` и ссылается на версию через `model_version_id`. Метрики во вкладке «Качество» относятся к проверке версии при обучении. Фактическая точность новых прогнозов измеряется после закрытия суток во вкладке «Мониторинг».

Чистый стенд при первом вечернем расчёте один раз обучает первую версию стандартной процедурой. Существующий стенд можно перевести на уже сохранённую версию:

```powershell
docker compose exec worker python -m backend.modeling.initialize_active --version <ID из реестра>
```

Команда заново строит признаки на дату этой версии. Затем сверяет контрольную сумму набора, параметры, метрики и архивный прогноз той же даты. Только после этого версия становится рабочей; запись попадает в журнал активаций. Без рабочей версии worker не публикует прогноз, а прежний прогноз остаётся доступен.
