# Подбор параметров и журнал экспериментов

Короткий ответ: команда подбирает параметры Ridge и CatBoost случайным поиском в пределах бюджета и записывает эксперимент в журнал. Итог виден во вкладке «Качество → Журнал экспериментов». Любой эксперимент повторяется по идентификатору.

```powershell
docker compose exec worker python -m backend.modeling.tuning --trials 16 --seconds 300 --seed 42
docker compose exec worker python -m backend.modeling.tuning --reproduce exp-20261113T160716-b39803
```

## Как устроен поиск (`random-search-v1`)

- Сначала проверяются параметры по умолчанию: Ridge с погодой (alpha 1) и CatBoost с погодой (глубина 5, шаг 0,05, 250 итераций). Затем идут случайные варианты обеих моделей, с погодой и без.
- Пространство поиска:
  - Ridge: alpha 0,01–100, логарифмическая шкала;
  - CatBoost: глубина 3–7, шаг 0,02–0,2 (логарифмическая шкала), 150/250/400 итераций, `l2_leaf_reg` 1/3/10.
- Бюджет — наибольшее число испытаний и наибольшее время. Поиск останавливается по тому ограничению, которое наступит первым. Последовательность вариантов задаётся seed.
- Каждый вариант оценивается на тех же трёх окнах по 28 дней, что и выбор модели. Обучение в каждом окне — только на более ранних закрытых сутках.
- Последние 28 дней в поиске не участвуют. Лучший вариант (по MAE окон) проверяется на них один раз, вместе с лучшим вариантом по умолчанию и прогнозом по прошлой неделе.

## Журнал

PostgreSQL, таблица `experiments`; в файловом режиме — `data/experiments/`. Запись неизменяема: повторно сохранить тот же идентификатор нельзя. В записи:

- бюджет и фактически потраченное время, seed и версия алгоритма поиска;
- версия данных: источник заказов, SHA-256 обучающей таблицы, период и число строк;
- пространство поиска;
- каждое испытание: модель, погода, параметры, MAE, WAPE, время;
- лучший вариант, лучший по умолчанию и результат на отложенных днях;
- версии библиотек.

Повтор `--reproduce` заново строит таблицу признаков на дату эксперимента и проверяет SHA-256. Затем пересчитывает каждое испытание и отложенную проверку и сверяет последовательность вариантов для этого seed. Любое расхождение выводится по пунктам.

`GET /api/experiments?limit=5` отдаёт последние записи журнала.

## Первый эксперимент — 13 ноября 2026 года

`exp-20261113T160716-b39803`: 16 испытаний за 3,8 секунды, данные `synthetic-weather-v2` по 11 ноября, 2 106 строк, seed 42.

- **Лучший вариант — Ridge с погодой, alpha 1, параметры по умолчанию:** MAE 6,79 на окнах.
- **Отложенные дни 15 октября — 11 ноября:** 6,35 против 10,96 у прогноза по прошлой неделе.
- **Остальные варианты:**
  - Ridge с погодой при alpha 0,03–0,04 — 6,82–6,83;
  - лучший CatBoost с погодой (глубина 7, шаг 0,024) — 7,07;
  - все варианты без погоды — 8,31–8,54.

Подбор подтвердил, что параметры по умолчанию выбраны разумно и что главный выигрыш даёт погода, а не настройка моделей. Повтор по идентификатору совпал полностью.

## Проверки

`test_tuning`:
- одинаковый seed даёт одинаковые испытания;
- изменение последних 28 дней не меняет ни одно испытание, а меняет только итоговую проверку;
- бюджет времени и пустой бюджет соблюдаются;
- запись не перезаписывается;
- повтор совпадает, а подмена метрики или данных обнаруживается.

HTTP-тест проверяет `/api/experiments`.
