# Контекст проекта для продолжения

Это существующее учебное приложение «Пульт доставки», тема 15 — доставка готовой еды. Продолжай текущую архитектуру: FastAPI, React/TypeScript/Vite, PostgreSQL, MinIO, Docker Compose. С пользователем общайся по-русски, коротко и понятно. В интерфейсе сначала давай вывод и действие, затем пояснение; технические подробности можно раскрыть отдельно. Сохраняй спокойную зелёную палитру.

## Существующие договорённости

- Заказы синтетические; оперативного источника и реальных маршрутов пока нет. Суточный прогноз не равен очереди заказов сейчас или личному заработку курьера. Погода общая для Москвы. Учебный пример должен оставаться явно подписанным.
- Исходный прогноз сохраняется до целевого дня; факт добавляется после закрытия суток. Не заменяй исторические наблюдения новым прогнозом задним числом.
- Серверные решения мониторинга неизменяемы по ключу версии правила, зоны и даты. При изменении алгоритма введи новую версию правила. Повторный запуск не должен дублировать результат.
- Общая логика признаков должна сохраняться для обучения и прогноза. Учитывай вечернюю отсечку и незавершённые сутки. Не используй будущие данные при оценке, отборе признаков или проверке кандидата.
- Тестовые аккаунты и искусственные сдвиги данных создавай в изолированных схемах/каталогах. Не очищай рабочие тома, аккаунты, аватары или журналы. Не запускай `docker compose down -v` для обычного обновления.
- Не публикуй `.env`, рабочие данные, аватары или ключи. GitHub origin уже настроен. Не придумывай историю коммитов за прошедший семестр.
- Главный экран курьера, прогноз, качество, мониторинг, журнал, аккаунт и админка должны сохраняться. Не своди всё приложение к новой странице.

## Проверки и запуск

```powershell
npm --prefix frontend test
npm --prefix frontend run build
docker compose build
docker compose run --rm --no-deps -e PULT_DATABASE_URL= -e "PULT_TEST_DATABASE_URL=host=db dbname=pult user=pult" web python -m unittest discover -s backend/tests -v
docker compose up -d --wait --wait-timeout 90
```

Команда тестов предполагает запущенные db/MinIO и собранный текущий образ. `PULT_TEST_DATABASE_URL` создаёт собственную временную схему; `PULT_DATABASE_URL=` отключает рабочую БД для файловых тестов. Без тестового подключения HTTP-тесты пропускаются — такой прогон нельзя описывать как полную проверку интеграций. В GitHub Actions тест MinIO пропускается, локально он проверяется настоящим сервисом.

Рабочий адрес: `http://127.0.0.1:8765`. После изменения UI проверь его в поддерживаемом браузерном инструменте, включая узкий экран. После изменений схемы сначала должен отработать Compose init. Заканчивай этап точным описанием изменений, выполненных проверок и того, что действительно осталось.
