# Пульт доставки

Учебная прогнозно-аналитическая система по дисциплине «Проектный практикум», тема № 15 — «Доставка готовой еды». Каждый вечер в 20:00 по Москве пульт прогнозирует число заказов на завтра в шести зонах доставки. Он показывает, где прогноз выше плановой мощности, объясняет прогноз и следит, не стала ли модель ошибаться чаще.

- **Пользователь** — диспетчер, который вечером решает, в какие зоны добавить курьеров.
- **Данные.** Заказы синтетические и явно подписаны, но спрос зависит от настоящей погоды в Москве: дождь и холод добавляют заказы. Погода — Open-Meteo. Зоны на карте собраны из реальных административных округов Москвы.
- **Стек.** Python (FastAPI, scikit-learn, CatBoost), React + TypeScript, PostgreSQL, MinIO, Docker Compose.

Репозиторий: [Dmitroooo73/Courier_Slot](https://github.com/Dmitroooo73/Courier_Slot).

## Запуск одной командой

Нужен установленный и запущенный Docker Desktop.

~~~powershell
git clone https://github.com/Dmitroooo73/Courier_Slot.git
cd Courier_Slot
docker compose up -d --build
~~~

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765).

При первом запуске worker загружает год учебных заказов и архив погоды. Затем он обучает первую рабочую модель, публикует прогноз и строит учебный цикл обновления модели. Это занимает несколько минут и требует интернета для Open-Meteo. Пока расчёт идёт, пульт показывает базовый демопрогноз. Ход работы: `docker compose logs -f worker`.

- Если прогноз не вышел через 30 минут после 20:00 или планировщик молчит дольше 10 минут, на всех аналитических вкладках появляется красное предупреждение. Контейнер worker в `docker compose ps` становится `unhealthy`.
- Остановить с сохранением данных: `docker compose down`. Данные лежат в томах `postgres_data`, `avatar_data` и в папке `data/`.
- Не используйте `docker compose down -v` для обычного обновления: эта команда удаляет базу и аватары.
- Занят порт 8765: `$env:PULT_PORT = "8768"` перед запуском, затем откройте порт 8768.
- Обновить после изменения кода: `docker compose up -d --build`. Init сам создаст новые таблицы.

## Что где в пульте

| Вкладка | На какой вопрос отвечает |
| --- | --- |
| **Курьер** (открывается первой) | Стоит ли курьеру переезжать в другой район? Без свежих данных о заказах и дорогах совет не даётся; есть явно вымышленный пример. [Подробнее](docs/courier-scenario.md) |
| **Прогноз** | Где завтра не хватит мощности? Карта Москвы, зоны сверх плана, прогноз выбранной зоны и «Почему такой прогноз?» — вклад каждого признака |
| **Качество** | Насколько можно верить прогнозу? Средний промах в заказах, сравнение моделей, факт и прогноз, важность признаков, сценарий «Что изменится, если…», рабочая версия модели, реестр и журнал подбора параметров |
| **Мониторинг** | Не испортилась ли модель? «По заказам» — сверка прогноза с фактом. «Изменение данных» — дрейф входов. «Учебный сценарий» — скачок спроса в браузере. «Замена модели» — полный цикл обновления на учебных данных |
| **Журнал** | Что загружалось и когда? Каждый запуск с этапом, источниками и ошибкой |
| **Аккаунт / Админка** | Вход, профиль, аватар; администратор управляет пользователями и может запустить проверку новой версии модели или вернуть предыдущую |

Выдать роль администратора зарегистрированному аккаунту: `docker compose exec web python -m backend.admin ЛОГИН`.

## Как это работает

~~~mermaid
flowchart LR
    Orders["Журналы событий заказов<br/>(слабоструктурированный текст)"] --> Worker
    Weather["Open-Meteo<br/>архив прогнозов, JSON"] --> Worker
    Worker["worker · по расписанию<br/>загрузка → проверка → признаки → прогноз"] -->|"CSV, ответы API"| Files[("data/<br/>сырые данные")]
    Worker -->|"прогнозы, факты, решения,<br/>версии моделей, журнал"| DB[("PostgreSQL")]
    Registry["Реестр моделей<br/>рабочая версия"] --- DB
    Worker -->|"обучает новую версию<br/>по сигналу мониторинга"| Registry
    Web["web · FastAPI"] <--> DB
    Web <-->|"аватары"| Media[("MinIO")]
    Web -->|"погода сейчас"| Weather
    UI["Браузер · React"] <-->|"HTTP API"| Web
~~~

1. **Сбор.** Журналы событий заказов (текст со служебными строками и повторами) разбираются в суточные CSV. Погода берётся из архива прогнозов Open-Meteo, выпущенных за 48 часов. Повторный запуск догружает только новые дни; временные ошибки и лимиты API повторяются, каждый запуск пишется в журнал.
2. **Проверка и признаки.** Уникальность заказов, полнота суток и часов погоды, необычный спрос. Признаки для обучения и прогноза считает одна функция `features_for_day`: заказы D−2, D−7, D−14, среднее за 7 закрытых дней, день недели, зона, погода. Вечером D−1 сутки D−1 ещё не закрыты, поэтому лаг 1 не используется.
3. **Модели.** Повтор прошлой недели (база), Ridge и CatBoost, каждая с погодой и без. Три окна по 28 дней для выбора и отдельные последние 28 дней для итоговой оценки. Метрики — MAE в заказах на зону за день и WAPE. [Технический отчёт](docs/report.md)
4. **Ежедневный прогноз.** В 20:00 сохранённая рабочая версия считает прогноз на завтра, без обучения. После полуночи факт сверяется с исходным прогнозом.
5. **Мониторинг.** Две недели промаха выше порога дают сигнал. Worker обучает новую версию и сравнивает её с рабочей на контрольной неделе, которой не было в обучении обеих. Замена — только при выигрыше от 5%; откат — одной кнопкой администратора. [Правила обновления модели](docs/model-lifecycle.md)
6. **Пульт.** FastAPI отдаёт готовые результаты из PostgreSQL, React обновляет их раз в минуту.

## Данные

| Источник | Что забираем | Как обновляем |
| --- | --- | --- |
| Синтетический журнал событий заказов (текст) → CSV | ID, время и зона заказа; служебные строки отбрасываются, повторно доставленные события не удваивают заказы | Генератор с seed=42 выдаёт журнал за каждые закрытые сутки: спрос зависит от зоны, дня недели и архивной оценки погоды ECMWF (последний расчёт модели на каждый час). Парсер проверяет полноту и пишет CSV |
| [Open-Meteo Previous Runs API](https://open-meteo.com/en/docs/previous-runs-api), JSON | Почасовые температура и осадки из прогноза за 48 часов → суточные признаки | Догружаются только недостающие даты; ответ сохраняется как есть |
| [Open-Meteo Forecast API](https://open-meteo.com/en/docs), JSON | Погода сейчас — только для показа диспетчеру | Не чаще раза в 10 минут, общий кэш |
| OpenStreetMap, границы округов | Карта зон | Собрана один раз, хранится в коде. [Подробнее](docs/map.md) |

Модель видит только прогноз погоды, выпущенный за 48 часов, а спрос — от архивной оценки погоды ECMWF (последний расчёт модели на каждый час), — как в жизни. Погода снижает средний промах примерно на четверть. Первая версия синтетики (без погоды) сохранена в архиве; прогнозы, выпущенные на ней, сверяются с её же фактами. Погода по Open-Meteo распространяется по лицензии CC BY 4.0, геоданные OpenStreetMap — по ODbL. [Данные и признаки](docs/data-and-features.md)

## Конфигурация

Значения по умолчанию заданы в `compose.yaml`, пример — `.env.example`. Перед развёртыванием не на своём компьютере задайте свои пароли.

| Переменная | Назначение |
| --- | --- |
| `PULT_PORT` | Порт пульта на 127.0.0.1, по умолчанию 8765 |
| `PULT_DB_PASSWORD` | Пароль PostgreSQL |
| `PULT_MINIO_USER`, `PULT_MINIO_PASSWORD` | Доступ к хранилищу аватаров |
| `PULT_MINIO_IMAGE` | Образ MinIO, если закреплённый недоступен |
| `PULT_AUTH_SECURE_COOKIE` | `1` — cookie входа только по HTTPS |
| `PULT_LIVE_WEATHER` | `0` — не запрашивать погоду «сейчас» (работа без интернета) |
| `PULT_DATA_DIR`, `PULT_DATABASE_URL` | Каталог данных и подключение к базе для запуска без Docker |

## Полезные команды

~~~powershell
docker compose ps                                   # состояние сервисов
docker compose logs -f worker                       # расписание, расчёты, ошибки
docker compose exec worker python -m backend.daily --date 2026-11-13           # опубликовать пропущенный прогноз; готовый не меняется
docker compose exec worker python -m backend.modeling --date 2026-11-13         # обучить и сохранить версию для сравнения
docker compose exec worker python -m backend.modeling.demo_cycle --force       # пересчитать учебный цикл замены модели
docker compose exec worker python -m backend.modeling.tuning --trials 16 --seconds 300 # подбор параметров с бюджетом, запись в журнал
docker compose exec worker python -m backend.modeling.tuning --reproduce <ID>          # повторить эксперимент из журнала
docker compose exec worker python -m backend.modeling.verify_reproduction --version <ID>   # обучить версию из реестра заново и сверить
docker compose exec worker python -m backend.modeling.verify_reproduction --date 2026-11-11 # повторить архивный отчёт обучения
~~~

`verify_reproduction` и `tuning --reproduce` заново генерируют заказы во временной папке или берут сохранённые и сверяют SHA-256 данных, выбор модели, метрики и прогнозы. Идентификаторы версий — во вкладке «Качество → Реестр моделей», экспериментов — в «Журнале экспериментов».

## Проверки

~~~powershell
npm --prefix frontend test
npm --prefix frontend run build
docker compose build
docker compose run --rm --no-deps -e PULT_DATABASE_URL= -e "PULT_TEST_DATABASE_URL=host=db dbname=pult user=pult" web python -m unittest discover -s backend/tests -v
~~~

Тесты с базой создают собственную временную схему `pult_test_*` и удаляют её; рабочие таблицы и аккаунты не затрагиваются. Без `PULT_TEST_DATABASE_URL` HTTP-тесты пропускаются. GitHub Actions запускает те же тесты с PostgreSQL и сборку интерфейса. Результаты приёмки — в [requirements.md](docs/requirements.md).

## Запуск без Docker

Python 3.11+ и Node.js 20.19+ / 22.12+:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt -r requirements-ml.txt
npm --prefix frontend ci
npm --prefix frontend run build
.\.venv\Scripts\python.exe -X utf8 -m backend.daily            # загрузка, первая модель, прогноз в data/
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
~~~

Без `PULT_DATABASE_URL` всё хранится в JSON внутри `data/`; аккаунты и админка требуют PostgreSQL. `backend.daily --watch` включает расписание. Самый первый прогон без библиотек машинного обучения: `python -X utf8 -m backend.pipeline` — базовый прогноз «как неделю назад» на 24 октября 2026 года по сохранённому выпуску погоды.

## Структура

~~~text
backend/
  pipeline/    загрузка заказов и погоды, проверки, хранение, мониторинг, дрейф
  modeling/    признаки, обучение и выбор моделей, объяснения, реестр, рабочая версия, учебный цикл
  routers/     HTTP API: прогноз, модели, аккаунты
  services/    аккаунты, аватары, погода сейчас
  tests/       модульные и интеграционные тесты
frontend/src/  страницы, компоненты, типизированные запросы, геометрия карты
docs/          отчёт, правила и решения по каждому модулю
tools/         сборка карты из OpenStreetMap
~~~
